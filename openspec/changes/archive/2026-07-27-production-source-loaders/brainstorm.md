## Design Summary

Phase 7 of the dual-deployment-operator: implement the two **production source loaders** behind the existing `internal/source` seams so the operator renders real sources end-to-end, replacing the test-only fakes and the `TODO(production-loaders)` stub in [`cmd/main.go`](../../../cmd/main.go). Two independent implementations are added: a Helm `ChartLoader` that pulls charts from **both OCI registries (`oci://`) and classic HTTP(S) Helm repositories** — each a first-class, tested path — **pulling to a temp dir and cleaning up each call (no caching in this change)**, and a kustomize `RootResolver` that fetches a pinned-`?ref=` git root with **go-git** (pure-Go, no `git` binary). Both gain **full authentication** — real, wired, tested paths (not off-by-default stubs) — sourced from a per-source `authSecretRef` on the CRD, supporting **basic/token auth only** (git SSH deferred; Helm-repo TLS knobs deferred). **Source caching is deferred to Phase 7.5** (see Key Decisions). The `GetEventRecorderFor → GetEventRecorder` deprecation migration rides along as a distinct final task. This unblocks Phase 8 (equivalence tests need real renders of all 5 operators) and any live in-cluster run.

The renderer logic and the `Source`/`ChartLoader`/`RootResolver` interfaces are **unchanged** — this change is purely additive production implementations behind those interfaces, plus the CRD `authSecretRef` fields and the `cmd/main.go` wiring.

## Alternatives Considered

### Option A: Both loaders in one change, full auth, basic/token auth only (chosen)
- **Approach**: Implement the Helm ChartLoader (OCI + classic HTTP(S) repos, both first-class) and the go-git kustomize RootResolver together in one change; build real authentication for both (OCI basic-auth, HTTP-repo basic/token, git HTTPS basic/token) sourced from a per-source CRD `authSecretRef`; **no caching (both loaders fetch fresh each reconcile — caching deferred to Phase 7.5)**; git SSH auth and Helm-repo TLS knobs deferred; recorder migration bundled as a distinct task.
- **Pros**: Keeps Phase 7 whole so Phase 8 (equivalence for all 5 operators) is unblocked in one cycle; egress unknown resolved (qa smoke test); auth is complete and tested rather than a dead stub; the two loaders are independent behind separate interfaces so they don't entangle.
- **Cons**: Larger diff (two loaders + auth + CRD fields + tests); a breaking `v1alpha1` CRD change (adding `authSecretRef`).
- **Why chosen**: The main reason to hesitate on the kustomize path — seed→github egress — was verified available on qa-de-200 (conditional on Gardener networking labels). Bundling avoids a second spec cycle and keeps Phase 8 unblocked. Full auth (not stubs) was an explicit user decision to avoid shipping a half-wired seam.

### Option B: Helm loader only; defer kustomize RootResolver to a follow-up change
- **Approach**: Ship the 4-operator OCI path now; make ipam-capi's git resolver its own later change.
- **Pros**: Smallest, fastest PR; cleaner review; no git/go-git dependency yet.
- **Cons**: Splits Phase 7 into two spec cycles; leaves Phase 8 blocked on the second (equivalence tests need ipam-capi's real kustomize render too).
- **Why not chosen**: The egress blocker that motivated deferral is resolved, so there's no longer a reason to split. Keeping Phase 7 whole is simpler end-to-end.

### Option C: Both loaders, but anonymous-only (no auth), credential seams deferred
- **Approach**: Implement both loaders with no credential support at all — rely on the verified-anonymous keppel + public-github paths; add auth later when a private source appears.
- **Pros**: Smallest correct change for today's fleet (all 5 operators are anonymous, verified); no untestable stub code; no CRD change.
- **Cons**: When a private source lands, auth becomes a second change touching the same code + CRD.
- **Why not chosen**: User chose full auth now (Option A) over anonymous-only. The deciding principle: don't ship a half-wired credential seam — either build auth properly (real paths + real tests) or omit it entirely. Given the choice, the user opted to build it properly this change.

## Agreed Approach

**Option A** — both production loaders in one change, with full, real, tested authentication (basic/token only), classic HTTP(S) Helm repos as a first-class tested path, and the recorder migration as a distinct final task. **Caching was originally in scope (a disk-backed tgz cache) but was removed after review (see Key Decisions) and deferred to Phase 7.5** — both loaders fetch fresh each reconcile. Credentials come from a per-source `authSecretRef` on the CRD (mirroring the existing `shootAccess.secretName` convention), resolved per host into the library-native auth type. All new code lives in `internal/source/`; the only edits outside it are the CRD `authSecretRef` fields (+ regenerated artifacts) and `cmd/main.go` wiring.

## Key Decisions

- **Both loaders in one change**: egress verified, keeps Phase 8 unblocked in one cycle. (User: "a".)
- **go-git for the kustomize root fetch**: pure-Go, explicit `?ref=` pinning, fail-closed on unresolvable ref, no `git` binary in the image; matches how Flux solves the identical problem. krusty still fetches the *transitive* bases itself — the resolver supplies only the root. (User: "a".)
- **Classic HTTP(S) Helm repos are a first-class, tested path**: `Load` dispatches on repo scheme — `oci://` → registry client; `http(s)://` → `action.Pull` with `RepoURL` + `Username`/`Password`. Basic/token auth only; **TLS knobs (`CaFile`/`InsecureSkipTLSverify`) deferred** — add with their own test if a repo needs a custom CA. Both paths pull a `.tgz` into a temp dir that is loaded then cleaned up (no cache — see below). A real classic-repo test tier (local static `helm repo index` server, anonymous + authed) covers it. (User: "we should allow classic helm repo" + "A" = basic auth only, no TLS knobs.)
- **Caching REMOVED from this change → deferred to Phase 7.5** (reversal of an earlier decision): originally scoped as a disk-backed LRU tgz cache. During review the discussion evolved — a *sound* cache should key on a **resolved** immutable id (git commit SHA via `ls-remote`, OCI digest), not the mutable ref/version string, and the highest-value form caches the kustomize *render* (skipping krusty's transitive fetches), not just the chart artifact. That is a distinct feature with its own soundness design (transitive-tag immutability) and belongs symmetrically across both loaders. So Phase 7 ships **no cache** (both loaders fetch fresh each reconcile); the resolve-then-key, `emptyDir`-backed, symmetric cache is scoped as **Phase 7.5 "Source caching"**. (User: "skip the whole cache topic in this change and scope it immediately after this phase" + "phase 7.5".)
- **Full authentication, real and tested — not stubs**: build `RegistryCredentials` (OCI) and `GitCredentials` (git HTTPS) as wired paths with real integration tests (self-hosted authed OCI registry; local authed git server), plus a token-non-leaking error assertion. Either build auth properly or omit it — no half-wired seam. (User: "b".)
- **git auth is HTTPS-only; SSH deferred**: `http.BasicAuth{Username, Password}` (PAT → Password, or user+pass). No `ssh.NewPublicKeys`, no host-key-verification surface (`InsecureIgnoreHostKey` is a security smell to ship), no `ssh-privatekey` Secret key. No current/foreseen source uses SSH. Documented as a future change. (User directive.)
- **Credentials come from a per-source `authSecretRef` on the CRD (Option A over operator-global)**: add optional `authSecretRef` to `HelmSource` and `KustomizeSource`, naming a Secret in the CR's namespace — mirrors the existing `shootAccess.secretName` convention and keeps the CR as the single config surface (design §3.3). Single `authSecretRef` per source; the Secret holds multiple keys (`username`/`password`/`token`); the resolver picks by what's present. Breaking `v1alpha1` change (free pre-release). (User: "A".)
- **OCI auth is inline, never `Login`**: use `registry.ClientOptBasicAuth(user, pass)` on a per-pull `registry.Client` (no filesystem write — the operator FS may be read-only; avoids the `Login` hostname-vs-URL gotcha). Always set a **non-nil** `RegistryClient` even for anonymous pulls (nil → panic in the Helm SDK). (Librarian-verified against helm v3.17.)
- **git SHA vs tag/branch ref pinning**: a tag/branch ref → shallow clone via `CloneOptions.ReferenceName` + `Depth:1`; a commit SHA → `PlainInit` + `CreateRemote` + `FetchContext(RefSpec "<sha>:<tempbranch>", Depth:1)` + `Checkout{Hash}`. Both **fail closed** — error if the ref can't be resolved, never silently build `HEAD`. (Librarian-verified against go-git v5.)
- **Recorder migration bundled as a distinct final task**: `GetEventRecorderFor → GetEventRecorder` (field-type change `record.EventRecorder → events.EventRecorder`, all call sites + test fake, drop the `//nolint:staticcheck`). Kept as its own task with its own success criterion so it doesn't blur into loader work. (User: "A".)
- **Online tests gated behind `DDO_ONLINE_TESTS`**: `make test` stays green offline (fakes + local git repo for resolver tests); the online tier (real keppel pull, real public-github resolve) runs in CI.

## Egress (resolved — documented in docs, not code in this change)

Seed→github egress was `design.md` §9 open question 1. **Smoke-tested 2026-07 on two seed landscapes** — `a-qa-de-200` (`shoot--cp--m-qa-de-200`) and `rt-qa-de-1` (`shoot--cp--m-qa-de-1`), the namespaces where the `-remote` operators run; both gave identical results: an **unlabeled** pod has no egress and cannot even resolve DNS (Gardener `deny-all` NetworkPolicy is the gate, not the WAN path); a pod carrying `networking.gardener.cloud/to-dns`, `to-public-networks`, and `to-private-networks` reached `github.com` git-upload-pack, `raw.githubusercontent.com`, and keppel — all HTTP 200. Resolution: egress is available **conditional on those three Gardener labels** — a Phase 9 chart requirement (pod template must stamp them), not operator code. Documented in `design.md` §9.1 (RESOLVED) and `docs/implementation.md` Phase 7 + Phase 9. No in-landscape git mirror needed for qa.

## Deferred Decisions (carried forward to Phase 7.5 "Source caching")

These decisions were reached during this change's brainstorm/design and then **deferred, not discarded**. They are the starting point for Phase 7.5 — record them so the next phase inherits the thinking rather than re-litigating it. None are implemented in Phase 7 (both loaders fetch fresh each reconcile).

- **Disk-backed, not in-memory.** Cache the pulled chart `.tgz` on disk (parse-on-hit via `loader.Load`), never an in-memory `*chart.Chart` LRU. Rationale: keeps only the currently-rendering chart's parsed objects in heap (transient, freed after render), suiting the ~200Mi per-shoot operator; and a disk "full" is a **catchable `ENOSPC`** (degrade to re-pull) whereas an in-memory "full" is an **uncatchable OOMKill** mid-reconcile.
- **Size-bounded LRU, no TTL, evict-before-write.** Bound by total on-disk size (proposed default **512 MB**, configurable). Evict least-recently-used entries in the same critical section *before* committing a new file, so on-disk usage never exceeds the cap by construction (no background sweeper). No TTL — immutable content makes time-expiry pure re-pull waste. A single chart larger than the whole cap is not cached (render from pulled bytes, skip storing).
- **Cache-write failures are non-fatal.** An `ENOSPC`/write error is logged and skipped; the loader still returns the pulled chart so the render succeeds and re-pulls next reconcile. The cache is an optimization, never the source of truth.
- **`emptyDir` volume (moved off Phase 9).** Chart 1's `deployment.yaml` mounts an `emptyDir` at the cache dir with `sizeLimit ≥ cap` so the cache is isolated from other ephemeral-storage consumers and cannot cause node disk pressure; the loader falls back to an `os.TempDir()` subdir when no volume is mounted. This coupling belongs with the caching impl (Phase 7.5), not the deployment-chart phase.
- **Resolve-then-key (the sound cache key).** Key the cache on a **resolved immutable id**, not the mutable ref/version string: git ref (`main`/tag/short-SHA) → concrete commit SHA via `ls-remote` (cheap `info/refs`, no clone); OCI `repo:version` → manifest digest via a `HEAD`/manifest request. A push / tag-move / version bump changes the resolved id → cache miss → re-fetch. Auto-invalidates, no TTL, sound for any ref kind.
- **Cache the render, not just the artifact (the high-value layer).** The bigger win is caching the kustomize **rendered `[]manifest`** keyed by resolved root SHA — this skips clone **and** krusty **and** the transitive `kubernetes-sigs`/`raw.githubusercontent.com` fetches (the expensive part), not just the small root clone. **Soundness caveat to design in 7.5:** the root SHA covers transitive refs only insofar as they are pinned in the committed kustomization files (they are for ipam-capi: `?ref=v1.1.0`, `v1.13.4`) — but those are *tags*, so a force-moved upstream tag under the same root SHA would serve a stale render. Decide in 7.5: (a) trust upstream release tags + document, or (b) resolve transitive refs to SHAs too (fully sound, more work). Start with (a).
- **Symmetric across both loaders.** Apply the same resolve-then-key + `emptyDir` pattern to Helm (chart artifact by resolved OCI digest) and kustomize (render by resolved root SHA) so the two sides aren't asymmetric.
- **Record the resolved id in status (valuable independent of caching).** Recording the resolved commit SHA / OCI digest per reconcile in `status` (or an Event) makes every render auditable/reproducible even with `?ref=main`. Consider landing this small piece first in 7.5; it needs no cache.
